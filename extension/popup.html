      How Tabduct works

      What it is

      Tabduct connects an AI coding agent (such as Claude Code) to the real Chrome you are already using. Instead of driving a fresh, empty browser, the agent works with the exact tabs you hand it — your sessions, your logins, your open pages — so it can help with things that normally need a signed-in browser.

      Quick start

      1. Start — click the button (or the header dot); it turns green.
      2. Point your agent at it — open Settings (⚙), copy the MCP endpoint + Authorization token into your agent's MCP config (template below), reload the agent.
      3. Share — Share Current Tab for one tab, or Share Everything. The agent can now work with what you shared, and nothing else.

      What the agent can do

      For a tab you have shared, the agent can read the page's text and a compact outline of its elements, take a screenshot, click, type, wait for things to load, read the console, navigate, run in-page scripts, and open/close tabs. Most of these work even on strict-CSP sites (GitHub, banks) — see below. Everything you have not shared stays completely invisible — it can't even see the title of an unshared tab. Several safety limits below can narrow this further.

      Sharing & how you stay in control

      • Two ways to share: Share Current Tab (just the tab you're on) or Share Everything (all current and future tabs). Sharing resets when you restart Chrome, so you never leave something shared by accident; reloading the extension (after an update) keeps what you shared.
      • Origin filter (Settings) decides which sites are eligible at all, and overrides every sharing mode:
        • Block mode (default): the listed sites are never shared — put your email, bank, etc. here.
        • Allow mode: flips it — only the listed sites can be shared, everything else is blocked (an empty allow list blocks everything). Best if you want the agent confined to a known set of sites.
      • Lock shared tabs to their domain (Settings, on by default): a shared tab that navigates to another site is paused — the agent is refused and the tab vanishes from its list, so a shared shopping tab can't quietly follow you into your bank; the share is kept and resumes when the tab is back. Turn it off to let the agent browse freely within a shared tab (it applies to tabs you already shared, immediately). Embedded frames on a shared page (e.g. a sign-up form served from another domain) stay reachable either way — the origin filter still applies to them.
      • Don't auto-share tabs the agent opens (Settings, on by default): tabs the agent opens itself aren't shared until you approve them, so it can't silently reach a brand-new site.
      • Read-only (Settings): the agent may look (read text, screenshot) but never click, type, navigate, run scripts, or open/close tabs.
      • Auto-expire (Settings): un-shares tabs after a time you pick (5 min … 10 h), counted from when each was shared or from when you changed the setting.

      Marking shared tabs & indicators

      • Header dot: green = running, red = stopped. Click it to start / stop.
      • Toolbar icon: plain = idle; green dot = the current tab is shared; red dot = Tabduct is stopped.
      • "⚡" tab group (Settings, on by default): shared tabs are gathered into a coloured ⚡ group. Drag a tab into the group to share it; to also unshare by dragging it out, switch that on in Settings.
      • Right-click a page → "⚡ Tabduct: share / unshare this tab" — the quickest way to toggle one tab.
      • Shortcut Ctrl+Shift+Y toggles sharing for the current tab.

      Strict-CSP sites & CDP mode (advanced)

      Clicking, typing, reading, and waiting work everywhere — they run as injected functions, which a site's Content-Security-Policy can't block. Only arbitrary JavaScript (execute_script) can be blocked by a strict CSP (GitHub, banks, most SaaS). For that, the Advanced settings offer opt-in CDP mode: eval bypasses CSP via the DevTools Protocol, with a developer mode that routes all eval through it and captures the full console (including uncaught errors and network/CSP warnings). It's OFF by default — nothing attaches until you flip the toggle. (Chrome does not allow requesting "debugger" at runtime, so it's a required permission granted at install; the toggle is what actually authorizes attaching.) While on, Chrome shows a "this tab is being debugged" banner (your signal), a "CDP" chip appears in the header, and it still obeys consent — never in read-only.

      Terminals & custom widgets (trusted input)

      Terminals (such as the one in AWS CloudShell) and many custom dropdowns or editors ignore scripted clicks and typing — they only react to input the browser itself generated. With Allow CDP eval on, the agent can send exactly that: type / click with trusted, and press_key (Enter, Tab, Ctrl+C…). It is refused while the page contains a frame of a site on your blocked list (even a hidden one), never pastes from your clipboard, and never works in read-only. Settings → Full access turns on the usual combination in one click (lock-to-domain off, read-only off, no expiry, CDP eval on); Safe defaults undoes it. Your blocked-origins list is never touched.

      Starting Tabduct

      Click Start (or the header dot). Tabduct launches a small server on your own machine — nothing is exposed to the internet — and shows an endpoint URL and a secret token in Settings. Point your agent at those. Click the dot again to Stop it (the server process exits).

      Shared hub: Tabduct always exposes one fixed endpoint (127.0.0.1:12311) with a stable token, so your agent config never changes — and every browser you connect appears behind that single endpoint (the agent tells them apart by their Label). Start Tabduct in one browser and any other browser you open joins that same hub automatically; you only ever point your agent at 127.0.0.1:12311.

      Configuring your agent (MCP)

      Tabduct speaks MCP (Model Context Protocol) over HTTP. After connecting, copy the exact endpoint and token from Settings, then add a server entry to your MCP client's config:

      {
  "mcpServers": {
    "tabduct": {
      "type": "http",
      "url": "http://127.0.0.1:12311/mcp",
      "headers": {
        "Authorization": "Bearer PASTE_TOKEN_FROM_SETTINGS"
      }
    }
  }
}

      Replace the token with the value shown in Settings once running (the endpoint is always the hub at 127.0.0.1:12311). Reload your agent and it will discover the Tabduct tools: list_tabs, get_active_tab, get_page_content, get_dom_snapshot, list_frames, screenshot, wait_for, click, type, press_key, navigate, open_tab, close_tab, activate_tab, get_console_logs, list_network_requests, get_network_request and execute_script.

      Add it at the global / user scope. Some agents (Claude Code included) scope MCP servers to the working directory you configured them in — so a second session started from another folder won't see Tabduct. Register it globally instead. In Claude Code: claude mcp add --scope user tabduct http://127.0.0.1:12311/mcp --header "Authorization: Bearer <token>" (or move an existing project entry to user scope). Cursor and most GUI clients already store MCP servers globally.

      Running several browsers or profiles

      Install Tabduct in each Chrome profile you want to use — each Google account / profile is separate. Start it in one browser; any other profile you open then joins the same hub automatically (no need to press Start in each). Share tabs per browser as usual. They all appear behind the one endpoint (127.0.0.1:12311) and the agent tells them apart by their Label (auto-named like Chrome-abcd). Give each a clear name in Settings — e.g. Work and Personal — so the agent (and you) never confuse them.

      The shared-tab list here is your control panel for all of them: it's grouped by browser (Current first, then each other browser that's sharing), so you see everything exposed across every profile at once. The ✕ next to a tab unshares it even on another browser; a browser sharing everything shows a single ⚡ Sharing all tabs row you can switch off the same way; and Revoke all sharing (the link at the bottom) clears every browser in one click. Managing other browsers travels over a separate, token-authed channel the agent never sees — it can only ever stop sharing, never start it.

      Good to know

      • The server listens only on 127.0.0.1 (your machine) and is guarded by the token — treat the token like a password and don't paste it into untrusted places.
      • The origin filter is the only thing that confines which sites the agent can reach. In Block mode with an empty list, an agent that can open tabs could reach any non-listed site — use Allow mode (or add sensitive sites to the block list) if that matters to you.
      • If the agent asks for a tab that isn't shared, is blocked, or has expired, it simply gets "not shared" and moves on — no error, no leak.
